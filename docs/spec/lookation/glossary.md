## 표기 규칙

- 출처 `[p.N]`은 `최종문서/04.PFINDER_요구조건분석서.pdf`의 N쪽이다(이하 "요구 PDF").
- `[기술 p.N]`은 `최종문서/07.PFINDER_기술문서.pdf`, `[정책 §...]`은 `공용공간/요구사항 및 정책/정책.docx`, `[최종 §...]`은 같은 폴더의 `요구조건분석서(최종).docx`의 절 번호다.
- 상태 값: 확정(원문에 정의가 있고 상충 없음) / 모호(정의가 불충분) / 충돌(문서 간 또는 문서 내 상충) / 미정의(용어만 등장).
- 정책 문서에만 있고 요구 PDF에는 없는 용어는 마지막 절에 따로 모았다.

## 정책 문서에만 있는 용어

요구 PDF에 정의나 등장이 없고 정책 문서(`정책.docx`)·최종 요구분석서에만 있는 용어다. 요구 PDF 기준 추적이 불가능하므로 `[p.N]`을 붙이지 않고 문서·절만 인용한다. 구현 전에 요구 PDF 개정판 반영 여부를 확인해야 한다.

| 용어 | 정의 | 출처 | 상태 | 비고 |
| --- | --- | --- | --- | --- |
| 승인예약 | 호스트가 예약을 승인한 뒤 결제하는 예약 방식 | `[정책 §이용자 3-3]` | 미정의 | 결제는 바로결제만 서술되어 있다 `[p.9]` → [V-INT-PAYMENT-01](validation.md#v-int-payment-01) |
| 찜공간 | 이용자가 저장해 둔 관심 공간 목록 | `[정책 §이용자 2-2]` | 미정의 | 검색 썸네일에 "찜 갯수"가 추가된다 `[정책 §이용자 3-4]`. 요구 PDF 썸네일 항목에는 없다 `[p.8]` |
| 대표계좌 | 블랙리스트 전환 시 자동환불 대상으로 쓰는 계좌 | `[정책 §관리자 3-2]` | 미정의 | 대표 지정 규칙이 없다. 계좌는 최대 3개 `[p.13]` |
| 운영 보고서 | 거래액·예약·회원·게시물 수를 기간별로 집계한 관리자 지표 | `[정책 §관리자 7-1]` | 모호 | 요구 PDF 관리자 장에는 보고서 요구가 없다 `[p.2]` → [V-REPORT-OPERATION-01](validation.md#v-report-operation-01) |

## 정리

- 같은 대상을 여러 이름으로 부르는 경우: 검수(등록 승인·인증), 블랙리스트(블랙), PIRI(DM·메신저·1:1문의), 공간(매물·공간 게시물), 이용완료(사용완료).
- 같은 말이 다른 대상을 가리키는 경우: "회원"(이용자+호스트 / 이용자만), "환전"(계좌 지급 / 충전·정산 전반), "예약취소"(취소 사건 / 환불까지 끝난 상태), "검수 완료"(승인 / 게시).
- 화면·API·DB 이름이 다른 경우: 회원고유코드 = `accountCode` = `member_code`/`host_code`, 블라인드 = `loc_blind_code`, 신고 = `loc_report_code`/`book_report_code`.
